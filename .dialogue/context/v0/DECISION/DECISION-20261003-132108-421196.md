The user stated that their Vercel Redis integration's defaults are KV_REST_API_URL and KV_REST_API_TOKEN and approved using these names directly rather than creating Upstash-named aliases. The implementation uses src/session-driver.ts as Astro's runtime driver entrypoint, reads the two variables from process.env when instantiated, keeps the gawd-blog:sessions namespace and throws explicit errors if either variable is absent. The build-time descriptor contains the entrypoint, not credentials. The custom driver replaced the earlier built-in-driver configuration without changing the selected Upstash storage backend.
