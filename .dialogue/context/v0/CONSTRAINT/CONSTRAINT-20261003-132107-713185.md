The implementation sets Vercel migrations.runtime to 'check', retains 'auto' locally and sets development migrations to 'auto'. EmDash documents that 'check' returns 503 when known migrations remain pending; concurrent function cold starts must not be the production migration mechanism. The proposed pipeline builds the Vercel artifact and generated .emdash/migrations.json, runs pnpm test:vercel, reviews migrate --status and the intended target fingerprint, runs migrate --expected-target-fingerprint and migrate --check, then promotes that same prebuilt artifact. Serialise per database; explicitly export the target credentials; do not blindly accept a newly generated fingerprint or cancel an in-flight migration. Keep the generated manifest ignored rather than committed, and prevent a separate Git auto-production path or Autobuild hook bypassing the gate. The pipeline was specified but not implemented or exercised against a live database during this session. Source: https://docs.emdashcms.com/deployment/core-migrations/.
