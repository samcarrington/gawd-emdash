Implemented Vercel build presence checks require EMDASH_SITE_URL, TURSO_DATABASE_URL, TURSO_AUTH_TOKEN, KV_REST_API_URL and KV_REST_API_TOKEN; missing required variables throw explicit errors. Turso values supplied to libsql are carried in server-side build descriptors, so rotation requires a rebuild. The session driver reads KV credentials at runtime and its descriptor contains no credentials. EmDash's s3 adapter resolves omitted S3_* settings at Node runtime. The documented S3 contract includes S3_ENDPOINT, S3_BUCKET, an actual S3_REGION rather than the default 'auto', and S3_ACCESS_KEY_ID/S3_SECRET_ACCESS_KEY when explicit credentials are used; S3_PUBLIC_URL is optional. The specification requires a stable EMDASH_ENCRYPTION_KEY, retaining the existing key when moving encrypted settings, and proposes EMDASH_TARGET_FINGERPRINT for migration authorisation. CRON_SECRET applies only if a scheduler endpoint is implemented. Do not use PUBLIC_ names, commit tokens or print secret-generation output. No credential values are included in these records. Sources: https://docs.emdashcms.com/deployment/storage/ and https://docs.emdashcms.com/deployment/secrets/#session-and-api-tokens.
